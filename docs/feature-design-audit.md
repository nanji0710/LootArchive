# 拾物集 ItemGlow 功能设计审查（第二版）：以「统计每个物品的价值」为唯一基准

> 审查对象：D:\GitHub\LootArchive（Android 原生，Kotlin 2.0 + Compose M3 + Room，93 个 .kt / 11,881 行，v6.11.0）
> 基准（唯一判据）：**统计每个物品的价值**。
> 判定规则：凡不服务于「把每件物品的价值录准、算对、看得见、守得住」的功能，进清单 A（多余）；凡该基准必需而项目里不存在的，进清单 B（缺失）。两条清单均按 P0 → P1 → P2 排序。
> 版本说明：**第一版结论（以「储物/找物」为基准）整体作废，不再沿用**；唯一保留的是第一版里的代码取证（文件:行号），第 5 节给出翻转对照。

## 时效性说明（2026-10-12 追加，阅读前请先看）

本文档的取证基于 **v6.11.0**，其后代码已发生下列变更，受影响条目的结论请按此校准（行号同理，以当前代码为准）：

1. **售出金额/售出日期机制已彻底移除**（`v6.12`，DB 迁移 v6 → v7，见 `docs/db-migration-notes.md`）。
   - §0 诊断中「资产总值 = 持有成本 + 卖出成交价」的混合口径、净值趋势把卖出额当正数累加、月度柱状图混入售出额 —— 这三处**已不复存在**，现行口径统一为「**当前拥有物品（在用/闲置/待修）的购入价之和**」。
   - **B-3 盈亏计算**、**B-4 口径拆三里的「已实现收益」一支**、**B-5 里「净值趋势含售出分量」的部分**：随机制移除而不再是「补能力」问题，而是「要不要重新引入卖出登记」的产品决策 —— 若未来要算赚赔，需要重新设计一处「卖出记录」（而不是恢复原字段）。
   - **B-14** 里「CSV 表头扩列」一项已不可能按原文实施：统计页的 CSV 导出模块已按用户指令整体移除。
2. **B-8「未估值态」已决策：不采用**（2026-10-12）。理由是统计基准要求每件物品都有价格，空价格会直接污染基准；录入页价格维持必填。
3. **清单 A 中已落地的剔除项**：A-3 游戏化、A-5 交互装饰、A-6 搜索三级 Chip 筛选层、A-8 标签独立录入、A-9 分类奖牌（技术方案与回滚方式见 `docs/feature-removal-plan.md`）。另按用户指令：移除统计页「数据导出」模块；「新增物品」由 3 步向导改为单屏（见 `docs/additem-flow-simplification.md`）。
4. 清单 B 中的其余条目（B-1 当前价值/估值日期、B-2 数量与单位、B-6 价值快照、B-7 多币种、B-9 凭证字段、B-10 价值维度、B-11 价格录入效率、B-12 批量估值、B-13 数据质量体检）**仍未实施**，仍可作为下一轮的功能输入。

## 0. 一句话诊断

**这个 App 的「价值统计」，实际是「支出统计」：它记录买东西花了多少、卖东西收了多少，但从不记录「现在值多少」。**

四行代码就是全部问题：

```kotlin
// app/src/main/java/com/nanji/lootarchive/ui/statistics/StatisticsViewModel.kt:70-76
val filteredTotalValue = filteredItems.sumOf { it.purchasePrice }          // 拥有物品的「购入价」
val saleRevenue = items.filter { ItemStatus.fromCode(it.status) == ItemStatus.SOLD && !it.isDeleted }
    .sumOf { it.salePrice ?: 0.0 }                                        // 已出物品的「卖价」
totalValue = filteredTotalValue + saleRevenue                             // 两者相加 = 「总资产」
```

- 全项目 grep `估值|现值|折旧|重估|currentValue|marketValue|valuation|depreciat` = **0 命中**；grep `盈亏|profit|收益率|gainLoss` = **0 命中**；grep `均价|中位数|median|average` = **0 命中**。全库唯一的价值字段是 `purchasePrice`（必填、≥0）与 `salePrice`（仅「已出」可填）。
- 于是「资产总值」= 手上物品的**历史成本** + 卖掉物品的**成交价**：卖掉的既不算资产（东西已经不在手上），也没扣掉它的成本（所以也算不出赚赔），只是一个混合数（HomeScreen.kt:96 首页 Hero 用的是同一口径）。
- 「资产净值趋势」折线图把**卖出收入当正数累加**（StatisticsScreen.kt:219-245：`runningTotal += 购入额 + 售出额`），卖掉东西会让「净值」上涨 —— 这条曲线在数学上只能单调上升，永远画不出下跌。
- 「月度购入趋势」柱状图同样把售出收入混进柱高（StatisticsScreen.kt:253-260：`purchaseByMonth + saleByMonth`），名为「购入」，实为「购入 + 卖出」。

**缺的不是某个字段，而是一条完整的价值链。** 现状对照：

| 价值链环节 | 应有能力 | 现状 |
|---|---|---|
| ① 录价 | 数量×单价、数字键盘、沿用上次、总价换算 | 只有一个普通文本框 + 必填校验（AddItemScreen.kt:450-464、AddItemViewModel.kt:201-205） |
| ② 价值本体 | 现值 + 估值日期（可回落购入价） | **不存在**（grep 0 命中） |
| ③ 汇总 | 持有成本 / 持有现值 / 已实现收益 三分 | 一个混合的 `totalValue`（StatisticsViewModel.kt:76） |
| ④ 盈亏 | 卖价 − 成本、收益率、已实现/未实现 | **不存在**（两个字段都在，但从不做减法） |
| ⑤ 趋势 | 现值时间序列（可涨可跌） | 「累计投入」冒充净值（只涨不跌，StatisticsScreen.kt:219-245） |
| ⑥ 凭证与交付 | 发票/序列号照片分类、渠道/SN、含现值与数量的导出 | 照片无类型（ItemPhotoEntity.kt:20-27）、CSV 表头无现值无数量（StatisticsScreen.kt:365） |
| ⑦ 守护 | 应用锁、加密备份、数据质量体检 | 无任何锁（grep BiometricPrompt/KeyguardManager = 0 命中），ZIP 为 file:// URI 明文分享 |

## 5. 与第一版的翻转对照（哪些结论不成立）

| 第一版结论（以「储物」判） | 第二版判定（以「价值」判） | 翻转原因 |
|---|---|---|
| 「购入价格必填且 ≥0」判为多余（A2），建议改选填并弱化 | **翻转**：价格是价值基准的唯一来源；应改为「必填但可标注未估值 + 增加现值与数量」 | 第一版认为记「东西放哪」不需要钱；价值基准下钱就是主题 |
| 统计页的金额图表判为次要（「记账」性质） | **翻转**：统计页是主干，但口径必须重写（B-4/B-5） | 它才是「统计每个物品的价值」的落点，缺失的是口径不是页面 |
| 「售出收益 + 售出日期」判为多余（A4），建议删两个字段 | **翻转**：它是盈亏计算的一半（B-3），必须保留并参与减法与趋势 | 没有它算不出「赚了还是亏了」 |
| 「最贵/最老物品」卡片判为装饰 | **翻转**：升级为「最贵物品榜」，直接回答「哪件最值钱」 | 它是全项目唯一在展示单件价值的地方 |
| 「数量 / stock」判为缺失 | **保留并升为 P0**（B-2） | 单价×数量是价值统计的基础口径 |
| 「位置层级 / 位置联想」判为缺失（P1） | **改为多余**（A-4） | 价值清单只需要一个位置文本；且现有联想实现是零引用死代码 |
| 「保质期 / 借出登记」判为缺失（P1） | **移出两条清单** | 它们不改变物品的价值，属另一条产品线；保留会稀释本基准的清晰度 |
| 「游戏化」判为次要装饰 | **升为多余 P0**（A-3） | 它以「填满字段」为目标，与「录准价值」直接争夺用户注意力 |
